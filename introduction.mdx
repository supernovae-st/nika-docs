**Nika is an open-source AI workflow runtime.** Define a workflow in a
`.nika` file, check it, run it on your infrastructure, and inspect its
results and execution record. Your files, models and permissions stay
under your control. Local execution needs no Nika account or hosted
service.

**Define → Check → Run → Inspect.** Coding assistants can help write the
file; the file is the contract you review and execute.

## Your first result

[Install the CLI](/getting-started/installation), then work in an empty
directory. This example calculates a total and writes `report.md` using
built-in tools. It needs no model, API key, account or network connection.

Save this as `report.nika`:

```yaml report.nika
nika: order-report
permits:
  tools: ["nika:jq", "nika:write"]
  fs:
    write: ["./report.md"]
const:
  orders:
    - {id: a, amount: 10}
    - {id: b, amount: 20}
tasks:
  summarize:
    invoke:
      tool: nika:jq
      args:
        input: ${{ const.orders }}
        expression: '{count: length, total: (map(.amount) | add)}'
  save:
    with:
      summary: ${{ tasks.summarize.output }}
    invoke:
      tool: nika:write
      args:
        path: ./report.md
        content: |
          # Order report
          Orders: ${{ with.summary.count }}
          Total: ${{ with.summary.total }}
outputs:
  summary: ${{ tasks.summarize.output }}
  report: ${{ tasks.save.output }}
```

Check the file, run it, and read the result:

```bash
nika check report.nika
nika run report.nika --output json
cat report.md
```

The run returns:

```json
{"report":"./report.md","summary":{"count":2,"total":30}}
```

The file contains:

```markdown
# Order report
Orders: 2
Total: 30
```

These are actual calculations and a file write, with no model or mock
response. Re-running replaces only the declared `report.md`. The
`with:` binding makes `save` wait for `summarize`; `permits:` names the
allowed tools and output file.

The run prints a trace path under `.nika/traces/`. Pass that exact path
to `nika trace verify` to inspect the record's integrity. A fresh machine
without a signing key reports **UNSEALED**, even when the hash chain is
intact. A successful verification does not establish that a model's
answer is correct. See [traces](/concepts/traces) for the evidence tiers.

Continue with [offline examples](/examples/offline) for known inputs and
exact expected outputs, or the [TypeScript quickstart](/sdk/start/quickstart)
to drive a local engine from an application. A persistent worker is
optional; the SDK's default local mode starts the engine directly.

## A real job, when you are ready

[Meeting actions](/examples/meeting-actions) turns a transcript into
typed, tracker-ready action items. It defaults to a local model
(`ollama/qwen3.5:4b`, no provider key — your own compute); point it at a
cloud provider and `nika check` prices the run before anything executes.
Same file shape as above; the model and tools change, the lifecycle does
not.

## What just happened, one concept at a time

1. **The file is the contract.** The verbs `infer`, `exec`, `invoke` and
   `agent` — nothing else: fetching a URL or writing a file is a *tool*
   under `invoke`, declared and auditable.
2. **Admission before execution.** `nika run` audits the file before anything
   executes; a refused file never starts. `nika check` is the
   same audit on its own, for CI.
3. **Permits are the blast radius.** `permits: {}` declares zero
   authority. A workflow that touches a file, a host or a shell must say
   so, or admission refuses it (`NIKA-AUTH-006`).
4. **Runs leave evidence.** Each run writes a hash-chained trace under
   `.nika/traces/`; `nika trace verify` inspects the record and reports whether it is sealed.
   Verification proves the record was not tampered with — not that a model
   was right.

## Ask the file three questions

<AccordionGroup>
  <Accordion title="What changes if a required input is missing?" icon="circle-question">
    The run refuses to start — the CLI exits 3 naming the missing key
    (`NIKA-1708`), the SDK throws `NikaOperationError`. Nothing is
    half-executed; a red admission never becomes a run.
  </Accordion>
  <Accordion title="What changes if a permission is absent?" icon="circle-question">
    The task that needs it is refused at check. An absent `permits:` block
    means zero authority — effects stay refused until the file declares
    them (`NIKA-AUTH-006`). `nika check --infer-permits` drafts the
    tightest block for you.
  </Accordion>
  <Accordion title="What changes if I switch the model?" icon="circle-question">
    One line. `mock/echo` rehearses offline, `ollama/qwen3.5:4b` runs
    locally, cloud providers take their env key. The file, the check and
    the receipt keep the same shape — `check` re-prices the run for the
    new seat.
  </Accordion>
</AccordionGroup>

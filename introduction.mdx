**Say what you want done. Keep it as a file.** Nika turns repeatable AI
work into a small `.nika` workflow you keep. Before anything runs, its check
shows what the workflow will do, which models and tools it uses, what it may
touch and what it can cost, without calling a model. You run it when you
decide, with the model you choose, local or cloud, and every run leaves a
tamper-evident record you can verify. One open-source binary: no Nika account
and no hosted service.

| 1 · Say it | 2 · Check it | 3 · Run it | 4 · Prove it |
|:---:|:---:|:---:|:---:|
| Describe the job in the [Session](/getting-started/session), or write the file | `nika check` audits it before any model is called | `nika run` with the model you choose | `nika trace verify` checks the run's record |

0.123 is the open-source reference release, maintained with security fixes,
bug fixes and compatibility work.

## Your first result

[Install the CLI](/getting-started/installation), then work in an empty
directory. This example calculates a total and writes `report.md` using
built-in tools. It needs no model, API key, account or network connection.

Save this as `report.nika`:

```yaml report.nika
nika: order-report
permits:
  tools: ["nika:jq", "nika:write"]
  fs:
    write: ["./report.md"]
const:
  orders:
    - {id: a, amount: 10}
    - {id: b, amount: 20}
tasks:
  summarize:
    invoke:
      tool: nika:jq
      args:
        input: ${{ const.orders }}
        expression: '{count: length, total: (map(.amount) | add)}'
  save:
    with:
      summary: ${{ tasks.summarize.output }}
    invoke:
      tool: nika:write
      args:
        path: ./report.md
        content: |
          # Order report
          Orders: ${{ with.summary.count }}
          Total: ${{ with.summary.total }}
outputs:
  summary: ${{ tasks.summarize.output }}
  report: ${{ tasks.save.output }}
```

Check the file, run it, and read the result:

```bash
nika check report.nika
nika run report.nika --output json
cat report.md
```

The run returns:

```json
{"report":"./report.md","summary":{"count":2,"total":30}}
```

The file contains:

```markdown
# Order report
Orders: 2
Total: 30
```

These are actual calculations and a file write, with no model or mock
response. Re-running replaces only the declared `report.md`. The
`with:` binding makes `save` wait for `summarize`; `permits:` names the
allowed tools and output file.

The run prints a trace path under `.nika/traces/`. `nika trace verify` reads
the latest one (pass a path to pick another) and checks the record's
integrity. A fresh machine without a signing key reports **UNSEALED**, even
when the hash chain is intact: run `NIKA_KEYCHAIN=off nika key init` once and
later runs report **SEALED** ([Seal your runs](/getting-started/installation#seal-your-runs)). A
successful verification does not establish that a model's answer is correct.
See [traces](/concepts/traces) for the evidence tiers.

Continue with [offline examples](/examples/offline) for known inputs and
exact expected outputs, the [terminal Session](/getting-started/session) to
describe a job in your own words, or the
[TypeScript quickstart](/sdk/start/quickstart) to run workflows from an
application. The SDK starts its bundled engine directly; no server is needed.

## A real job, when you are ready

[Meeting actions](/examples/meeting-actions) turns a transcript into
typed, tracker-ready action items. It defaults to a local model
(`ollama/qwen3.5:4b`, no provider key, your own compute); point it at a
cloud provider and `nika check` prices the run before anything executes.
`nika try meeting-actions` rehearses it offline, and the page lists what a
real run needs. Same file shape as above; the model and tools change, the
lifecycle does not.

## What just happened, one concept at a time

1. **The file is the contract.** The verbs `infer`, `exec`, `invoke` and
   `agent` — nothing else: fetching a URL or writing a file is a *tool*
   under `invoke`, declared and auditable.
2. **Admission before execution.** `nika run` audits the file before anything
   executes; a refused file never starts. `nika check` is the
   same audit on its own, for CI.
3. **Permits are the blast radius.** `permits: {}` declares zero
   authority. A workflow that touches a file, a host or a shell must say
   so, or admission refuses it (`NIKA-SEC-004`; with no `permits:` block at
   all, `NIKA-AUTH-006`).
4. **Runs leave evidence.** Each run writes a hash-chained trace under
   `.nika/traces/`; `nika trace verify` inspects the record and reports whether it is sealed.
   Verification proves the record was not tampered with — not that a model
   was right.

## Ask the file three questions

<AccordionGroup>
  <Accordion title="What changes if a required input is missing?" icon="circle-question">
    For an input marked `required: true` with no `default:`, the run refuses
    to start: the CLI exits 3 naming the missing key (`NIKA-1708`), and the
    SDK's `run()` throws `NikaOperationError`. Nothing is half-executed; a red
    admission never becomes a run.
  </Accordion>
  <Accordion title="What changes if a permission is absent?" icon="circle-question">
    The task that needs it is refused at check. An absent `permits:` block
    means zero authority — effects stay refused until the file declares
    them (`NIKA-AUTH-006`). `nika check --infer-permits` drafts the
    tightest block for you.
  </Accordion>
  <Accordion title="What changes if I switch the model?" icon="circle-question">
    One line. `mock/echo` rehearses offline, `ollama/llama3.2:3b` runs
    locally, and cloud providers take their environment key. The file, the
    check and the record keep the same shape; `nika check` re-prices the run
    for the new model, and asks for a larger `max_tokens` when a reasoning
    model needs room to think.
  </Accordion>
</AccordionGroup>

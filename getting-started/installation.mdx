<Warning>
  **Docs track main: v{STATUS.version}.** Homebrew installs the latest tagged
  release, which may intentionally lag main. Run `nika --version` and
  `nika --help` after install; those commands are the executable source of truth
  for your local binary. The `nika: v1` language envelope is stable.
</Warning>

## Install today

<Tabs>
  <Tab title="Homebrew">
    ```bash
    brew install supernovae-st/tap/nika
    ```
  </Tab>

  <Tab title="curl">
    ```bash
    curl -LsSf https://nika.sh/install.sh | sh
    ```
    Detects platform (macOS / Linux), prefers Homebrew when `NIKA_VERSION=latest`
    and Homebrew is available, then falls back to the GitHub release binary.
  </Tab>

  <Tab title="source">
    ```bash
    git clone git@github.com:supernovae-st/nika.git
    cd nika
    cargo test --workspace --lib
    ```
  </Tab>
</Tabs>

## First-run verification

```bash
nika --version
nika doctor    # providers + editor/agent readiness + exact fixes
nika init      # repo-local schema + agent rules
nika wire all  # explicit MCP wiring for supported clients
```

`nika init` scaffolds repo-local schema wiring, `AGENTS.md`, and Cursor rules.
`nika wire cursor` or `nika wire all` explicitly wires MCP clients. Installers
do not mutate editor configs automatically.

<Check>

  with SHA256 sums.
</Check>

## Provider keys

Nika needs a provider to run inference — local needs no key at all.

```bash
# Local · zero key (Ollama daemon)
ollama pull llama3.1

# Or export any cloud provider key (ephemeral)
export MISTRAL_API_KEY=...
export ANTHROPIC_API_KEY=sk-ant-...
```

See [Providers catalog](/reference/providers-catalog) for all
{STATUS.providers} providers with their env var names.

## What gets installed

- **`nika`** — the binary (single file, no daemon, no background process)
- **Nothing else.** No service, no telemetry, no home-dir pollution beyond
  files you explicitly create with `nika init` or `nika wire`.

## Uninstall

```bash
# Homebrew
brew uninstall nika

# Manual install
rm ~/.nika/bin/nika
```

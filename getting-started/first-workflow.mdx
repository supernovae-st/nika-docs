## Goal

Write a `.nika.yaml` file, run it, get structured output. No setup beyond
`nika` installed. **Your first run needs no API key and no model server.**

## 1. Pick how the AI step runs

Three paths, from zero-setup to production:

**Instant (no model at all)**: the built-in `mock/echo` model returns a
deterministic response, so you can see a workflow's shape right now:

```yaml
model: mock/echo
```

**Local (free · private)**: have [Ollama](https://ollama.com) running,
no API key, nothing leaves your machine:

```bash
ollama pull llama3.2:3b
```

**Cloud**: set any provider key:

```bash
export MISTRAL_API_KEY=...
# or export ANTHROPIC_API_KEY=... · any provider in the catalog
```

At any point, `nika doctor` tells you exactly what's wired and how to fix
what isn't:

```bash
nika doctor
```

All provider env vars listed in [Providers catalog](/reference/providers-catalog).

## 2. Write the workflow

Create `hello.nika.yaml`:

```yaml hello.nika.yaml
nika: hello

tasks:
  greet:
    infer:
      model: ollama/llama3.2:3b            # <provider>/<name> · local · swap for any cloud provider
      prompt: "Say hi to the chrysalis. Be brief."
```

Three things to notice:

- **`nika: <name>`** is the mark and the name — the language as the key, the workflow's kebab-case identifier as the value (no version to pin).
- **`tasks:`** is a map keyed by task id; each task declares one verb (here, `infer`).

## 3. Check it, then run it

```bash
nika check hello.nika.yaml   # the static audit: plan · cost · secrets · types · before a single token is spent
nika run hello.nika.yaml
```

`nika check` catches broken references, missing dependencies and schema
problems before any model is called, and points at the exact fix:

<Tip>
  No provider handy? Swap the `model:` line for `mock/echo`. Both commands
  work fully offline, and you can wire a real model later.
</Tip>

<Info>
  **Before a paid model.** `nika check --native-strict` until zero hints.
  Probe every new builtin on `mock/echo` first. Numeric facts are
  `type: integer` (`enum: [0, 1, 3]`), never `enum: ["0","1","3"]`.
  The model extracts facts — `nika:jq` or `nika:decide` is the law
  (`nika try 13-extract-then-law`). Pin markdown globs
  (`exclude: "**/README.md"`) before a fan-out infer. Then swap `model:`.
</Info>

### Read the story back (0.98+)

`nika explain <file>` narrates any checked workflow — the waves, the
**cost before a token is spent** (an unbounded task reads `FLOOR`, a
local model reads *unpriced — not « free »* — the whole vocabulary
lives in [Cost honesty](/guides/cost-honesty)), what it touches, and
the flight recorder hand-off. Captured verbatim against the released
`0.107.0` on the chain skeleton after one recorded run:

```text
cost before a token is spent
  bounded portion $0.0000 · no total ceiling · 1 uncapped
    think: ollama/llama3.2:3b has no catalog price — unknown stays unknown (never $0)
  local models: your compute · tokens unpriced — not « free »

flight recorder
  1 run in .nika/traces · latest:
  nika trace show .nika/traces/2026-08-02T01-11-53Z-7f42.ndjson
  nika trace verify <same file>   # prove the hash chain
```

The skeleton already caps the seat (`max_tokens: 800`) — the uncapped
part is the *unpriced* local model, and the report says so instead of
printing a fake `$0`. Swap in any priced cloud seat and the same report
reads `≤ $0.0005 worst case · ≥ $0.0005 cheapest path` — a hard
ceiling.

## 4. Add a second task that depends on the first

```yaml hello.nika.yaml
nika: hello

tasks:
  greet:
    infer:
      model: ollama/llama3.2:3b            # <provider>/<name> · local · swap for any cloud provider
      prompt: "Say hi to the chrysalis. Be brief."

  critique:
    with:
      greeting: ${{ tasks.greet.output }}  # the binding IS the edge
    infer:
      model: ollama/llama3.2:3b            # <provider>/<name> · local · swap for any cloud provider
      prompt: |
        The greeting was: ${{ with.greeting }}

        Rewrite it shorter and more enigmatic.
```

Notice the `with:` block. Each `${{ tasks.X.* }}` reference in it is a
[binding](/concepts/bindings): it **names the data** the task consumes
(`${{ with.greeting }}` in the prompt) and **declares the edge** that
orders it — greet → critique, one declaration, no invisible edges. The
engine injects the value at runtime, with explicit taint tracking.

### The graph you just built

```mermaid
%%{init: {'theme':'dark','themeVariables':{'background':'transparent','mainBkg':'transparent'}}}%%
flowchart LR
    classDef task fill:#3F7DFF,color:#fff,stroke:#7FE9FF,font-weight:bold
    G["greet<br/>infer"]:::task --> F["critique<br/>infer"]:::task
```

One `with:` binding and the order falls out of the file. Tasks with no
edge between them run **in parallel automatically**. You never schedule
anything. (For an ordering with no data — run the deploy after the tests,
consume nothing — use `after: { tests: success }`, the control door.)

## 5. Get structured output

```yaml hello.nika.yaml
nika: hello-structured

tasks:
  names:
    infer:
      model: ollama/llama3.2:3b            # <provider>/<name> · local · swap for any cloud provider
      prompt: "Generate three names for a butterfly."
      schema:                          # structured output · JSON Schema
        type: object
        properties:
          names:
            type: array
            items:
              type: string
              minLength: 3
              maxLength: 20
            minItems: 3
            maxItems: 3
        required: [names]
```

Nika takes the JSON Schema, asks the provider for output that conforms
(using each provider's native structured-output API where the [capability
rules](/reference/capabilities) allow it: schema mode, object mode, or
JSON-mode emulation), and validates the result against your schema before
passing it on.

```bash
nika run hello.nika.yaml
# Output is guaranteed to be { "names": ["...", "...", "..."] }
```

## What you just built

- Workflows are YAML files: `.nika.yaml`.
- Tasks are units of work; the map key is the identity.
- Four verbs (`infer`, `exec`, `invoke`, `agent`) define what each task does (HTTP fetch is the `nika:fetch` builtin under `invoke`).
- `with:` (data) and `after:` (control) build the DAG — the binding IS the edge.
- `${{ tasks.X.output }}` crosses a task boundary in `with:`; the body reads `${{ with.<name> }}`, with taint tracking.
- `schema:` enforces JSON schemas on AI output.

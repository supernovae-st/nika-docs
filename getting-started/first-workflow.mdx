**Goal:** write one file, run it offline, read a typed output. No API key,
no model server, nothing leaves your machine.

<Info>
  **v{STATUS.version}:** `nika check`, `nika run`, `nika doctor`, `nika lsp`,
  and `nika mcp` ship in the binary. Run `nika init` once per repo for schema
  and agent rules. [Install Nika](/getting-started/installation) first if you
  have not.
</Info>

## 1. Write the file

Create `hello.nika`:

```yaml hello.nika
nika: hello
model: mock/echo        # rehearsal model: echoes the prompt, no network
permits: {}             # explicit: this workflow touches nothing
tasks:
  greet:
    infer:
      prompt: "Say hello to a new user, briefly."
      max_tokens: 32
outputs:
  greeting: ${{ tasks.greet.output }}
```

- **`nika: <name>`** is the mark and the workflow's kebab-case identifier.
- **`model: mock/echo`** needs no key and no server — the engine echoes the
  prompt back. The mechanics are real; the "answer" is a rehearsal.
- **`permits: {}`** declares zero authority up front. A workflow that later
  touches a file, a host or a shell must say so here, or admission refuses
  it.
- **`max_tokens`** caps the answer's length.
- **`outputs:`** names what the run hands back.

## 2. Check it, then run it

```bash
nika check hello.nika   # static audit — before a single token is spent
nika run hello.nika
```

Captured on v{STATUS.version}, offline — the audit is fully green
(`permits {} · est out ≤$0.0000 · 0 hints · risk low`), then:

```text
  ✔  greet  infer · mock/echo  1ms
  1 task · 1 wave · 0 retries · 9 tok
  ── 1/1 done · unpriced (1 call) · elapsed 0.0s ──
    wrote .nika/traces
    said "mock(echo) · Say hello to a new user, brief…"
    rehearsal · a mock model echoed the prompt — not a real answer
    trace: .nika/traces/2026-09-19T13-20-21Z-06c2.ndjson · 6 events · chain 08cf2534… · sealed
```

`nika check` catches broken references, missing dependencies and schema
problems before any model is called, and points at the exact fix. The run
wrote a hash-chained journal under `.nika/traces/`. Verifying that exact
journal — `nika trace verify .nika/traces/2026-09-19T13-20-21Z-06c2.ndjson`
— answered `OK · chain intact` and `SEALED` on this machine (exit 0):
tamper-evidence about the record, re-executing nothing. Verification
reports the evidence available to it; a missing run-signing key or a
mismatched receipt changes the verdict, not the run's result.

## 3. Ask the file three questions

<AccordionGroup>
  <Accordion title="What if a required input is missing?" icon="circle-question">
    Declare `inputs:` on the file and the run refuses to start without
    them (`NIKA-1708`, exit 3) — admission fails, nothing half-executes.
    Callers pass values with `run(..., { inputs })` in the SDK or
    `--var key=value` on the CLI.
  </Accordion>
  <Accordion title="What if a permission is absent?" icon="circle-question">
    The task that needs it is refused at check (`NIKA-AUTH-006`). An
    absent `permits:` block means zero authority — effects stay refused
    until the file declares them. `nika check --infer-permits` drafts the
    tightest block for you.
  </Accordion>
  <Accordion title="What if I switch the model?" icon="circle-question">
    One line. `ollama/qwen3.5:4b` runs locally after
    `ollama pull qwen3.5:4b`; a cloud provider takes its env key
    (`export OPENAI_API_KEY=...`). The file, the check and the receipt
    keep the same shape — only the answer changes. `nika doctor` reports
    what your machine can reach.
  </Accordion>
</AccordionGroup>

## 4. Add a second task that depends on the first

```yaml hello.nika
nika: hello
model: mock/echo
permits: {}
tasks:
  greet:
    infer:
      prompt: "Say hello to a new user, briefly."
      max_tokens: 32

  critique:
    with:
      greeting: ${{ tasks.greet.output }}  # the binding IS the edge
    infer:
      prompt: |
        The greeting was: ${{ with.greeting }}
        Rewrite it shorter.
      max_tokens: 32
```

The `with:` block is a [binding](/concepts/bindings): it names the data the
task consumes and declares the edge that orders it — greet → critique, one
declaration, no invisible edges. Tasks with no edge between them run in
parallel automatically. (For ordering without data — deploy after tests,
consuming nothing — use `after: { tests: success }`.)

## 5. Get structured output

```yaml hello.nika
nika: hello-structured
model: mock/echo
permits: {}
tasks:
  names:
    infer:
      prompt: "Generate three names for a butterfly."
      max_tokens: 200
      schema:                          # structured output · JSON Schema
        type: object
        properties:
          names:
            type: array
            items:
              type: string
              minLength: 3
              maxLength: 20
            minItems: 3
            maxItems: 3
        required: [names]
outputs:
  names: ${{ tasks.names.output }}
```

The engine asks the provider for output that conforms (using each
provider's native structured-output mode where the [capability
rules](/reference/capabilities) allow it) and validates the reply against
your schema before passing it on. The mock validates too — it synthesizes
a conformant instance, so this exact file runs offline. Captured on
v{STATUS.version} (`nika run hello.nika --output json`):

```json
{"names":{"names":["mock","mock","mock"]}}
```

On a **successful** run, `outputs:` carries the declared shape — checked
when the model answers. A failed or refused run produces no output: the
guarantee covers shape, not outcome.

## 6. See a real job

[Meeting actions](/examples/meeting-actions) turns a transcript into
typed, tracker-ready action items. It defaults to a local model
(`ollama/qwen3.5:4b`, no provider key — your own compute); point it at a
cloud provider and `check` prices the run before anything executes.
Same file shape as your hello; the model and tools change, the lifecycle
does not.

## What you just built

- Workflows are YAML files: `.nika`.
- Tasks are units of work; the map key is the identity.
- Four verbs (`infer`, `exec`, `invoke`, `agent`) define what each task
  does (HTTP fetch is the `nika:fetch` builtin under `invoke`).
- `with:` (data) and `after:` (control) build the DAG — the binding IS the
  edge.
- `${{ tasks.X.output }}` crosses a task boundary in `with:`; the body
  reads `${{ with.<name> }}`.
- `schema:` checks AI output shape at answer time; `outputs:` exports the
  result.

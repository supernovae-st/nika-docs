`nika welcome` summarizes your workspace and suggests a next command.
`nika doctor` reports environment observations and fixes you can choose to run.
Both stay offline unless you explicitly request a network probe.

## Read the environment

```bash
nika welcome
nika doctor
nika doctor --verbose
```

The report depends on your machine. Provider keys are reported by presence,
without printing their values. An unset key is advisory: without a workflow,
Doctor cannot know which provider you need. `--verbose` expands those notes.

| Observation | What it establishes |
|---|---|
| Configured provider | The provider and its effective route are recognized. |
| Listening port | A connection succeeded; the service behind it may be unrelated. |
| Compatible model list | The endpoint answered a validated model-list request. |
| Advertised model | The response named that model; inference has not been tested. |
| Verified run trace | The recorded chain verifies; business correctness needs its own oracle. |

## Probe local model servers

```bash
nika doctor --ping --json
```

The opt-in probe checks local ports and sends a bounded GET to each configured
local-protocol model-list endpoint. It does not send inference prompts, download
models, follow redirects or retry a failed request. It sends no provider key;
URL userinfo, query and fragment are removed from model-list requests.

The response distinguishes a compatible empty list, advertised models, an
incompatible response and an observation that could not complete. JSON exposes
`local_model_probes`; each observation includes `inference_tested: false`.
A listening port or an advertised model does not prove a working inference path.

Each model-list request has a total deadline and a response-size limit. A timeout,
unrelated HTML page or HTTP error stays unverified instead of becoming a success.
Doctor reports what it observed; it does not choose or authorize a model for a Run.

## Run an offline control

```bash
nika compile hello hello.nika
nika check hello.nika
nika run hello.nika
nika trace verify
```

This starter uses `mock/echo`: no provider account, model download or inference
request. It exercises the workflow and trace path. A mock result is not an AI answer.
Trace verification reads existing evidence and does not create a seal.

## Apply a fix explicitly

Doctor prints proposed commands and does not execute them. For example, after
reviewing the proposed client configuration:

```bash
nika wire cursor
```

That separate command writes MCP wiring while preserving existing server entries.
A Doctor report does not itself grant network, execution or spending authority.

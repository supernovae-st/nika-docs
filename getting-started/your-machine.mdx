Nika never asks you to configure blind. Two commands read your machine
offline, by presence only, and hand you the next step: `nika welcome` is the
short mirror, `nika doctor` the full diagnosis with a fix line for each gap.

## The mirror

```bash
nika welcome
```


Read it from the top:

- **The recommendation.** The first lines name one way to a real answer for
  this machine. **Nika Gear One** is an open-weights local model sized to your
  memory that `nika model pull` downloads and that needs no API key: here a
  7.4 GB Gemma 3 12B file for an 18 GB machine. Local inference is unpriced,
  not free: it runs on your hardware. Other rows appear when Nika detects a
  signed-in agent app or a provider key. A key's row reads
  `OPENAI_API_KEY is set · not checked until the first call`: nothing here
  calls the provider, so a revoked key only shows on that first call. See
  [Local models](/guides/local-models#gear-one-the-pick-nika-welcome-proposes)
  for the sizes, and the one limit of serving them.
- **`Next:`** is the line to type now: <code>{STATUS.firstCommand}</code>
  writes a starter file offline, without any key or model call.
- **`this machine`** names each gap and the command that closes it, never a
  vendor to buy from.
- **`this binary`** opens with the binary that is running: its version and
  commit, the installer it came from and its path. When another `nika` on your
  `PATH` differs from it, a second line says so and sends you to
  `nika doctor`. The counts below it are derived from the embedded language
  pack, never typed by hand. Its providers are the ones this build can drive:
  {CANON.providersLocal} local servers and {CANON.providersCloud} cloud APIs,
  without `mock`. The specification names {CANON.providers}
  providers, counting `mock`, the rehearsal provider that makes no model
  call. `nika catalog` lists {STATUS.providers} entries and marks the ones
  this build cannot drive as catalog only; `nika check` refuses those.
- **The five-line workflow is real**: an engine test pins that it checks
  clean. It appears only while your workspace has no workflow.

`nika welcome --json` emits the same mirror for programs (`welcome_version: 1`),
and `--ascii` swaps every glyph for plain characters. Nika has no hosted
service and none is planned: every path the mirror names runs on your machine
or with a provider key you choose.

## The diagnosis

```bash
nika doctor
```

Three rules shape the report:

- **Presence, never values.** A key is reported set or unset; its value is
  never read into a variable, so it cannot reach your terminal, a log or a
  trace.
- **Offline by default.** The base report touches nothing on the network.
  `--ping` (opt-in) probes the local servers you can configure: a connect to
  each loopback port, then a bounded `GET` of its model list. It runs no
  inference, downloads nothing and never contacts a vendor endpoint.
- **Diagnose only.** Doctor prints fixes and never runs them. `nika wire` and
  `nika key init` are the explicit commands that change something.

Warnings are not failures: with no workflow in hand, doctor cannot know which
provider, agent app or editor you need, so it lists every path you could
take. `nika doctor --verbose` unfolds the `advisory` line with a fix for each
note.

| Row | What it tells you |
|---|---|
| `binary` | The engine is self-contained: spec, schema, examples and templates are embedded. |
| `running` · `path` | Which `nika` is running: its resolved path, version, commit and installer (`install.sh`, `homebrew`, `npm-global`, `npm-payload`, `cargo`, `nix`, `release-dir`, `source-build`, or `unknown`), and what typing `nika` runs. Every other `nika` on `PATH` gets a row with the version it reports, and a warning with a repair hint when it is another build; a removal is suggested only for a known install layout. Each copy is asked `--version` under a two-second deadline, from `/` and with no credential in its environment: one that hangs reads unknown, one that fails warns, neither is fatal. `--json` adds `running`, `others[]` and `others_truncated`. |
| `access` | The access classes `--access` accepts, and the agent apps (harness seats) this build can drive. |
| `sandbox` | The sandbox this host has (Seatbelt on macOS, bubblewrap on Linux). A `permits:` file with `exec:` does not start on a host that cannot confine it (`NIKA-1710`). |
| `run-key` | Whether runs will be signed. Captured without a terminal, as above, it says `the keychain is not opened without a terminal`; in a macOS terminal it says `the keychain is not opened by this ad-hoc build`, even for the signed release: 0.123.2 never opens the keychain on macOS. `NIKA_KEYCHAIN=off nika key init` mints the key every process reads ([Seal your runs](/getting-started/installation#seal-your-runs)). |
| `sidecar` · `models` | Nika's built-in local inference, and whether a model is pulled for it. |
| `traces` | Run-record retention under `.nika/traces/`: the last N per workflow, an age cap, a size budget, each with its environment override. |
| `registry` | The agent clients the binary knows, how many `nika wire` can write, how many this machine was probed for. |
| `local` | The local servers that need no key, only a running process. |
| `image` · `tts` | The media backends. `mock` always works, so media workflows can be tested without keys. |
| `pricing` | The embedded price snapshot (rules, providers, date, digest): list rates, read with no network call. |
| `runtime` | One row per agent app: installed or not, signed in or not, and the `--access` seat that uses it. |
| `advisory` | Folded notes: unwired agents, unset keys (by presence), configuration defaults. |

## Probe the local servers

The `local` row says the providers need a running server; `--ping` checks
whether one is there. Each probe connects to the default loopback port (300 ms
cap), then asks the server for its model list with one bounded `GET` of
`/v1/models`. Here Ollama is running with no model pulled:

```text
$ nika doctor --ping
✔ ping       ollama — listening on 127.0.0.1:11434 (0ms)
⚠ ping       lmstudio — nothing listening on 127.0.0.1:1234
⚠ ping       llamacpp — nothing listening on 127.0.0.1:8080
⚠ ping       localai — nothing listening on 127.0.0.1:8080
⚠ ping       vllm — nothing listening on 127.0.0.1:8000
⚠ models     ollama — compatible model list · no model advertised
…
```

An open port is not taken for an engine on its own: a server that answers a
web page instead of an API reads
`accepts connections … but answers a page, not an API … — not a model server`,
a `401` or `403` reads `key-protected`, and a `404` reads
`no /v1/models route` (the `nika model serve` sidecar has none).

One reachable server with a model is a fully local inference path: no key, no
cloud, no account. [Local models](/guides/local-models) sets one up.

## For scripts and agents

Every fact above ships as JSON; agents and CI branch on `summary.fail` instead
of parsing glyphs:

```bash
nika doctor --json
```

## The fixes that change something

Doctor never edits a configuration. When a row says `fix: nika wire cursor`,
that command, and only that command, writes the MCP wiring, idempotently,
keeping whatever other servers the file already lists:

```bash
nika wire detected --dry-run   # preview the clients this machine shows
nika wire detected             # wire them
nika wire cursor               # or one client by name
```

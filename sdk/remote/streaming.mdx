```ts
for await (const event of nika.events(run, { bufferSize: 64 })) {
  render(event)
  if (event.sequence !== undefined) {
    await persistSequence(run.id, event.sequence)
  }
}
```

`NikaEvent` is open to additive fields and event kinds. Render only what the
application understands, preserve sequence when it is present, and use
`run.done` for terminal truth.

Each subscriber has a bounded queue. If a consumer falls behind, the SDK
throws `NikaEventBufferOverflowError` rather than silently losing evidence.

## Stop one view

```ts
const controller = new AbortController()

for await (const event of nika.events(run, {
  signal: controller.signal,
})) {
  render(event)
}
```

The signal stops only this subscriber. Call `nika.cancel(run)` to ask the
server to cancel engine work.

## Resume from application state

```ts
const recovered = await nika.attachRun(jobId, {
  lastEventId: lastCommittedSequence,
})
```

The HTTP adapter uses the persisted cursor for SSE continuity. The application
owns when a sequence is durable.

A `paused` settlement closes the current stream and resolves `run.done` with
that leg's result and evidence. The durable job can later resume under engine
authority; a new attachment can observe that later leg. Replaying or attaching
after the settlement event has already been consumed still reads the full
stored settlement. Stopping a stream or attaching to a job never answers a
human gate.

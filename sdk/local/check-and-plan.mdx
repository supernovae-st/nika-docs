import { SDK, LocalContract } from "/snippets/_sdk-contract.mdx"

```ts
const report = await nika.check('workflows/release.nika', {
  model: 'mock/echo',
  nativeStrict: true,
})

if (!report.clean) {
  console.error(report)
  process.exit(report.exitCode ?? 2)
}
```

`NikaCheckResult` deliberately stays open:

```ts
interface NikaCheckResult {
  report_version?: number
  clean?: boolean
  exitCode?: number
  verdicts?: NikaCheckVerdicts   // valid · access_ready · capacity_fit · run_ready · blockers · network_tasks
  [key: string]: unknown
}
```

A local check returns the engine's whole report (`report_version: 1`): the
same audit `nika check --json` prints. The fields an application usually
reads, measured on engine 0.123.0:

| Field | What it holds |
|---|---|
| `clean` · `exitCode` | the verdict: `true` and `0`, or `false` and `2` with findings |
| `findings[]` | each finding's `code`, `gate`, `task`, `message` and `severity` |
| `verdicts` | the four layers `nika check` prints: valid, access ready, capacity fit, run ready; `blockers`; and, from engine 0.124.1, `network_tasks`: the tasks whose own effects can still reach the network (a fetch or webhook to a real host, an MCP tool, a paid media call), which a `mock/echo` rehearsal does not stub |
| `permits` | `declared` (the file's `permits:`), `needed` (what its tasks reach) and `partial` |
| `cost` | `bounded_total_usd`, `min_path_total_usd`, `has_unbounded` and per-task rows |
| `requirements` | the models, secrets and required inputs the run needs |
| `risk_grade` | the engine's summary grade (`low`, `supervised`, `high`, `unbounded`) |

Pass `access` to judge the access plan under a pin, as `nika check --access`
does:

```ts
const pinned = await nika.check('workflows/release.nika', { access: 'mock' })
console.log(pinned.clean, pinned.verdicts?.access_ready, pinned.verdicts?.blockers)
```

A pin the engine refuses keeps `clean: true` (the file holds) with
`verdicts.access_ready: false`, and `verdicts.blockers` names the refusal in
the engine's words ([Access pins](/sdk/reference/configuration#access-pins)).

Apart from `clean`, `exitCode` and `verdicts`, the SDK types these fields as
`unknown`: narrow them in your code. Findings
are report data; configuration, engine resolution, transport and protocol
failures throw typed errors. Keep application policy outside the SDK, and
preserve unknown fields when storing or forwarding the report.
[Permits and admission](/sdk/runtime/permits) shows a complete policy check.

<Warning>
  The SDK has no separate dry-run-plan method. Do not manufacture a
  TypeScript plan contract from engine output. Use `check()` for admission
  and `nika run <file> --dry-run --json` (`plan_version: 1`) when an operator
  needs the CLI's plan.
</Warning>

Remote checks intentionally reject the local-only `model` and `nativeStrict`
overrides rather than silently ignoring them.
For a contained served name, the remote result is the resident's typed
acknowledgement or workflow refusal, without local findings or an exit code.
An explicit local path instead captures a local engine report and snapshot;
successful capture requires the resident to acknowledge that exact snapshot.
See [remote checks](/sdk/remote/client) for the two forms.

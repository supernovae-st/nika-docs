## Admit, observe and settle

```ts
const run = await nika.run('workflows/release.nika', {
  maxCostUsd: 0.25,
})

const watching = (async () => {
  for await (const event of run.events()) {
    timeline.accept(event)
  }
})()

const result = await run.result()
await watching

if (!isNikaRunSucceeded(result)) {
  // 'failed' and 'paused' both land here — a pause carries no success exit
  process.exit(result.exitCode || 1)
}
```

`run()` admits the workflow first — a file that fails admission throws
`NikaOperationError` and no handle is created. The returned `NikaRun`
carries `id` plus the observation methods; the run itself is not an async
iterator. Subscribe through `run.events()`; the result for this observation
leg lives in `run.result()`. The result's `settlement` carries the engine's
cause, task tally, spend, elapsed time and error when available. A `paused`
result closes observation at a human gate without claiming the workflow can
never resume.

## Stop observation without cancelling

```ts
const observer = new AbortController()

for await (const event of run.events({
  signal: observer.signal,
  bufferSize: 64,
})) {
  timeline.accept(event)
}
```

Aborting the observer stops only that view. It never cancels engine work.

## Cancel explicitly

```ts
const cancellation = await run.cancel()
const result = await run.result()

console.log(cancellation.accepted, result.status)
```

Cancellation is idempotent for a run owned by this client. Passing a run from
another client instance throws `NikaRunOwnershipError`.
`cancellation_requested` acknowledges the action, not its outcome. Keep
awaiting `run.result()`: the actual runtime result may be cancelled,
succeeded, failed or paused. A missing runtime settlement after the
resident's grace period is reported as interrupted rather than fabricated
cancellation.

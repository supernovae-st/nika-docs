Three surfaces can sound like a server. They do different jobs and accept
different clients.

## Truth table

Measured 2026-08-23 against `nika 0.114.0 (b1154df75)` — the GitHub release a
reader downloads. Engine `origin/main` was `80d62b8f` that afternoon (later
than this tag). Pages follow the binary, not `main`.

| Surface | Job | Status on 0.114.0 |
|---|---|---|
| `nika serve` (no `--bind`) | Fires armed local workflows from the `nika.yaml` project clock | Live · **not HTTP** |
| `nika serve --bind` + `--workflows` + `--token-file` | Authenticated loopback HTTP · jobs, SSE, OpenAPI | Live · **holes named below** |
| `nika model serve` | Hosts a local model behind an OpenAI-compatible inference endpoint | Live · a model provider, not a job API |

The OpenAPI document the binary serves (`GET /v1/openapi.json`) describes
itself as *Authenticated loopback remote execution. Cancel and artifacts are
absent.* Never say “remote execution” without those 404s.

## What `--bind` actually answers

Owner-only token file (`chmod 600`). Bytes never enter argv. A 20-character
token was refused (`server credential source refused`); a 48-byte owner-only
file was accepted.

| Route | Measured |
|---|---|
| `GET /health` | 200 · no auth · `{status, service: nika-serve, engine_version, build_sha, api_version}` |
| `GET /v1/openapi.json` | 200 · bearer |
| `GET /v1/workflows` | 200 · `{"workflows":[…filenames]}` |
| `GET /v1/workflows/:name` | 200 when `:name` is the contained filename (`hello.nika.yaml`) |
| `POST /v1/jobs` | 202 with `Idempotency-Key` + a contained `.nika.yaml` path · 400 without the header |
| `GET /v1/jobs/:id` | 200 after admit · id, status, execution_id, trace_id |
| `GET /v1/jobs/:id/status` | 200 · status only |
| `GET /v1/jobs/:id/events` | 200 `text/event-stream` · sequence / kind / status frames |
| `GET /status` | **404** `route not found` |
| `GET /events` | **404** `route not found` (SSE lives under the job id) |
| `GET /v1/jobs` (list) | **404** `route not found` |
| `POST /v1/run` | **404** `route not found` |
| `POST /v1/jobs/:id/cancel` | **404** `route not found` |
| `GET /v1/jobs/:id/artifacts` | **404** `route not found` |

```sh
nika serve --bind 127.0.0.1:18765 \
  --workflows ./workflows \
  --token-file .nika/serve.token
```

## Local application path

<LocalContract />

```ts
import { LocalNika } from '@supernovae-st/nika-client/local'

const nika = new LocalNika({ cwd: process.cwd() })
const result = await nika.runToEnd('workflow.nika.yaml')
```

This path requires no daemon.

## Local model path

```sh
nika model serve --model Qwen/Qwen3-0.6B-GGUF
```

The engine calls that inference endpoint as a provider. Application code does
not submit workflow jobs to it.

Three surfaces sound like servers but accept different clients.

| Surface | Job | HTTP workflow API |
|---|---|---|
| `nika serve` without `--bind` | Fires the `nika.yaml` project clock | no |
| `nika serve --bind` | Authenticated resident jobs and schedules | yes |
| `nika model serve` | OpenAI-compatible local inference provider | no |

## Released OpenAPI routes (0.124.3, default server)

| Method and path | Contract |
|---|---|
| `GET /health` | unauthenticated health and supported capabilities |
| `GET /v1/openapi.json` | authenticated contract document |
| `POST /v1/check` | compact admission acknowledgement or typed workflow refusal |
| `POST /v1/compile` | stateless authoring: a candidate and a source-only check preview; creates no job and writes no file. Deterministic by default; on a server started with `--authoring-model`, a caller may opt in to one provider round (`/health` lists `compileNativeV2`, and `GET /v1/openapi.json` then also describes `CompileRequestV2`) |
| `POST /v1/jobs` | idempotent admission |
| `GET /v1/jobs/{id}` | durable job projection |
| `GET /v1/jobs/{id}/status` | current status |
| `GET /v1/jobs/{id}/events` | SSE event stream |
| `POST /v1/jobs/{id}/cancel` | cancellation action; 202 remains pending, 200 returns a completed observation |
| `GET /v1/jobs/{id}/trace/verify` | the CLI verifier's verdict on the journal the server wrote for that job |
| `GET /v1/jobs/{id}/artifacts` | a settled job's artifact manifest, read from its sealed journal and bound to its receipt |
| `GET /v1/jobs/{id}/artifacts/{name}` | one artifact's bytes, streamed and checked against the size and SHA-256 its journal records |
| `GET /v1/workflows` | contained names |
| `GET /v1/workflows/{name}` | path-free metadata |
| `GET /v1/access-offers/{name}` | what the sessions of that workflow's own declared ACP route offer now, read without a prompt (`/health` lists `accessSessionOffer`) |
| `GET /v1/schedules/{id}` | schedule status |
| `PUT /v1/schedules/{id}` | CAS-backed schedule apply |

The contract has no `POST /v1/run`, job-list, schedule-list, schedule-delete,
trigger or backfill routes, and no artifact upload or deletion.
`GET /v1/jobs/{id}/trace/verify` answers in the CLI's words, lower case: `ok`
(intact, but unsigned or sealed with a key the server does not weigh: `reason`
reads `unsealed` or `unattributable`), `sealed`, `anchored` and `replayed`
hold; `incomplete`, `tampered` and `broken` do not; `unavailable` means the
server holds no journal for that job. Both artifact routes answer only for a
settled job whose journal verifies sealed:
[Outputs and artifacts](/sdk/remote/artifacts) covers the client side, and the
[server runbook](/sdk/operations/server-runbook#artifact-downloads) what the
door exposes.

```sh
nika serve --bind 127.0.0.1:18765 \
  --workflows ./workflows \
  --token-file .nika/serve.token
```

Useful flags beyond these three: `--state-root <dir>` (job state, default
`.nika/serve`), `--run-cost-ceiling <USD|none>` (per-job spend cap, default
1 USD), `--allow-remote` (acknowledge a non-loopback `--bind`; TLS belongs to
a reverse proxy) and `--authoring-model <provider/name>` (seat provider
authoring for `POST /v1/compile`). `nika serve --help` lists every flag.

## Ask what a route offers

A workflow file can declare how its model calls travel: `run.access` (`via`,
`protocol`, `fallback`, `service_tier`) and `run.reasoning.effort`. A run
learns what its session offers on the way to its prompt, and says so only when
it refuses. From engine 0.124.3 a server can be asked first:

```ts
const offer = await nika.accessOffer('workflows/brief.nika')
if (offer.status === 'not_applicable') {
  console.log(offer.reason)            // the file selects no ACP sessions
} else {
  for (const route of offer.routes) {
    if (route.status === 'unavailable') {
      console.log(route.profile, route.code, route.reason)
      continue
    }
    console.log(route.profile, route.model.status, route.effort?.offered, route.service_tier?.offered)
  }
}
```

- **The route is the file's.** The call names a served workflow and nothing
  else. The server asks only when the file declares `run.access.via` under
  `run.access.protocol: acp`; any other workflow answers
  `status: 'not_applicable'` with the reason, and no session is opened.
- **No prompt is sent.** The server opens each session as a run opens it,
  selects the file's model for that session only, lists what the session has
  for that model and ends it. `prompts_sent` is always `0`.
- **One row per session shape and model.** `completion` is the route's
  one-shot profile, which `infer:` tasks run under; `agent` is its agent
  session, which `agent:` tasks run in. `tasks` names the tasks of each row.
- **`effort.offered` is exact.** It holds the values a run accepts on
  `run.reasoning.effort` for that model. `effort.current` is what a run that
  declares no effort keeps on a session like this one. `service_tier.offered`
  holds the language's words, `standard` and `fast`.
- **A model the session does not list is a state, not an error.**
  `model.status` is then `not_offered`, with the models it does list in
  `model.offered`, and the efforts and tiers are `unobserved`.
- **A session that gives no offer is a row.** `status: 'unavailable'` carries
  the code a run would meet before its prompt (`NIKA-1803`, `NIKA-1804` or
  `NIKA-1805`) and a reason.
- **A row has a time.** `observed_at` and `fresh_until` say when it was read
  and until when the server serves it again: 60 seconds, 15 when unavailable.
  One reading runs at a time on the server, and a ninth concurrent request is
  refused with `NikaOperationError` (`access_offer_busy`).

The call has its own deadline, 100 seconds by default (`timeoutMs`), because a
first reading opens a session per row, and `signal` stops it. It needs a
server that lists `accessSessionOffer`: on another server, and on the local
engine, it rejects with `NikaCompatibilityError` before any request.

An offer authorizes nothing. A model, an effort or a tier can leave a route
between the offer and the run: `run()` is admitted as before, and the run
selects, reads back and refuses on its own session.
[Harness access](/guides/harness-access#ask-a-served-route-what-it-offers)
shows the document the server answers.

## Local application path

<LocalContract sdk={SDK} />

```ts
import { Nika } from '@supernovae-st/nika'

const nika = new Nika({ cwd: process.cwd() })
const run = await nika.run('workflow.nika')
const result = await run.result()
```

This path needs no resident server. These examples target the published
`@supernovae-st/nika@0.124.3` npm package (bundled engine 0.124.3). The
standalone engine CLI releases independently.

## Local model path

```sh
nika model pull unsloth/Qwen3-4B-Instruct-2507-GGUF   # downloads into ~/.nika/models; prints the size first
nika model serve --model unsloth/Qwen3-4B-Instruct-2507-GGUF
```

`nika model serve` loads only models it has pulled (or a `.gguf` path), of
the Qwen3 family in 0.124.3, and serves them on `127.0.0.1:8712`. A workflow
reaches it as a local provider: export
`NIKA_LLAMACPP_BASE_URL=http://127.0.0.1:8712` and use
`model: llamacpp/<model id>`, as the banner prints. Application code does not
submit workflow jobs to it.

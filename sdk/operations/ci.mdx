The pull-request job should prove the file is clean, inspect the authority and
spend shape, then rehearse the graph with the mock provider.

## Admission script

```ts
import { Nika } from '@supernovae-st/nika'

const nika = new Nika()
const file = process.argv[2]
const report = await nika.check(file, {
  model: 'mock/echo',
  nativeStrict: true,
})

if (!report.clean) {
  console.error(report)
  process.exit(2)
}

const run = await nika.run(file, {
  model: 'mock/echo',
  maxCostUsd: 0,
})

for await (const event of run.events()) console.log(event)
const result = await run.result()
if (result.status !== 'succeeded') process.exit(result.exitCode ?? 1)
```

## Authority ladder

    └── mock run ── graph behavior · receipt
                         │ approved
                         ▼
protected job ───── provider secrets + deployment authority`}</pre>

The shown mock workflow needs no provider key. Rehearsal fixtures must also
have safe tool boundaries: a mock model does not disable external effects.
Protected execution receives only the authority its environment and workflow
declare.

## Pin and print both versions

```sh
./node_modules/.bin/nika --version
npm ls @supernovae-st/nika
```

Keep the engine and SDK release train visible in logs. Do not debug skew from
an implicit global binary — and do not `npm exec -- nika` an uninstalled
name: with no locked local package, npm would download whatever that name
resolves to. The direct `node_modules/.bin` path only ever runs the
lockfile's payload.

<Info>
  Commit the package lockfile and keep optional platform dependencies enabled.
  The local npm executable above resolves the project's installed package;
  it does not require a global CLI. Pin the SDK and native payload together.
  A newer standalone engine release does not update an existing npm install.
</Info>

A live event view is presentation. The engine-issued receipt on the terminal
result is the typed proof seam.

```ts
const run = await nika.run('workflow.nika.yaml')
const result = await run.done

if (!result.receipt) throw new Error('run did not issue a receipt')

await auditStore.write({ runId: run.id, receipt: result.receipt })

const verdict = await nika.traceVerify(result.receipt)
if (!verdict.verified) {
  throw new Error(verdict.output ?? verdict.reason ?? 'verification failed')
}
```

`NikaReceipt` is an opaque readonly record. The SDK never constructs it,
extracts a path from it, enriches it by reading a workflow, or implements
cryptography. It asks the authoritative engine to verify the object unchanged.

Local verification can return `verified` or `invalid`. The remote endpoint
currently returns a typed `unavailable` verdict with reason
`trace_journal_unavailable` because it has no path-free journal authority. The
diagnostic route exists; this is not a 404.

CLI trace inspection remains available for operators:

```sh
nika trace show .nika/traces/<run>.ndjson
nika trace replay .nika/traces/<run>.ndjson
nika trace export .nika/traces/<run>.ndjson
```

Replay reprojects recorded events; it never reruns the workflow.

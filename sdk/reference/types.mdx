## Run lifecycle

```ts
interface NikaRun {
  readonly id: NikaRunId
  readonly done: Promise<NikaRunResult>
}

interface NikaRunResult {
  id: NikaRunId
  status: NikaRunStatus
  transport: 'native-process' | 'http'
  exitCode?: number
  outputs?: Record<string, unknown>
  receipt?: NikaReceipt
  error?: NikaMachineError
  execution_id?: NikaExecutionId
  settlement?: NikaSettlement
  [key: string]: unknown
}
```

`NikaRunStatus`, `NikaEvent`, `NikaCheckResult` and engine-owned metadata are
additive. Known words aid completion without closing the vocabulary.

`NikaSettlement` preserves the engine's `status`, `cause`, `elapsed_ms`,
`tasks`, `spend` and `error` when present. Remote replay and attachment read
the stored settlement; a missing runtime settlement remains absent.
`paused` completes the observation represented by `done` while leaving the
durable job resumable. Branded `NikaRunId`, `NikaJobId` and `NikaExecutionId`
keep engine-issued identities distinct and remain assignable to `string`.

## Check and cancellation

`NikaCheckResult` is an open engine projection. A local check carries the
findings report and process `exitCode`. A served-name HTTP check carries
`clean: true` plus `status`, `snapshot_digest`, `root` and `units`, or
`clean: false` with a typed refusal in `error`; it does not invent a local
findings report or exit code.

`NikaCancelResult` describes action acceptance. Its `status` can be
`cancellation_requested` while execution continues toward its own settlement.
Use `run.done` for the actual result, including success racing cancellation.

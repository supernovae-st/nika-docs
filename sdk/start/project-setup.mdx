The SDK should make the project boundary visible, not dissolve it into
application objects. The root `nika.yaml` is the control plane — optional
for a first workflow, required once the project arms beats or sets policy.
Each `*.nika` file is executable workflow intent.

## Recommended layout

<div className="sdk-flight sdk-flight-compact">
  <span>PROJECT TREE · CONTROL PLANE + INTENT + PROOF</span>
  <pre tabIndex={0}>{`project/
├── nika.yaml                  # project profile + optional armed beats
├── workflows/
│   ├── daily-brief.nika  # workflow intent
│   └── release.nika
├── src/
│   ├── nika.ts                # Nika construction
│   └── release.ts             # product code
├── .nika/
│   ├── traces/                # run journals
│   └── arm/                   # firing ledgers + watermarks
├── package.json
└── .gitignore`}</pre>
</div>

- `nika.yaml` governs project-wide spend and the released reader profile this
  project uses.
- `workflows/` is reviewed as intent.
- `src/nika.ts` owns binary resolution and the working directory, not a
  second copy of project policy.
- `.nika/` is runtime state: run records, firing ledgers, server job state
  and, when you serve over HTTP, the server's bearer token. Ignore it in
  source control and mount it deliberately on a server.

## Found the project

A project file is one line: the project's kebab-case name. Create it and let
the engine read it back:

```sh
printf 'nika: my-project\n' > nika.yaml
./node_modules/.bin/nika arm
```

```text
nothing armed — /path/to/project/nika.yaml carries no `arm:` entry
```

`nika arm` reads and validates the project file and its cadences, reports
what is armed, and schedules nothing. Add policy as you need it, for example a
default spending ceiling for every run of the project:

```yaml nika.yaml
nika: my-project

ceiling: 0.50
```

<Note>
  `nika init` does much more than create `nika.yaml`: it writes about 30
  agent, editor and hook files and a starter workflow
  ([the full list](/getting-started/agents#nika-init-teach-the-repo)). Run it
  only when you want that scaffold.
</Note>

Add `arm:` when time or an event should start a workflow, and `traces:` or
`registry:` for run policy: one file carries both. The
[project file](/sdk/project/nika-yaml) and [arm registry](/sdk/project/arm-registry)
pages show copy-paste forms.

## Create one client

```ts
// src/nika.ts
import { fileURLToPath } from 'node:url'
import { Nika } from '@supernovae-st/nika'

export const nika = new Nika({
  bin: process.env.APP_NIKA_BIN,
  cwd: fileURLToPath(new URL('..', import.meta.url)),
})
```

`fileURLToPath` decodes percent-escapes and survives spaces in the path —
`new URL(...).pathname` does neither.

Binary resolution follows one ladder:

1. `bin` passed to the constructor
2. `NIKA_BIN`
3. exact optional platform package

Use an explicit application variable for packaged services. `bin` and
`NIKA_BIN` must be absolute paths: a bare name or a relative path throws
`NikaConfigurationError`, and a `nika` on your `PATH` is never used. `cwd`
anchors relative workflow paths, project-file discovery and the `.nika/`
state directory.

## Probe at startup

```ts
try {
  const report = await nika.check('workflows/daily-brief.nika', {
    nativeStrict: true,
  })
  if (!report.clean) {
    console.error('workflow refused at admission', report.findings)
    process.exit(2)
  }
  console.info('nika engine ready')
} catch (error) {
  console.error('cannot start workflow runtime', error)
  process.exit(3)
}
```

A missing binary is an environment failure (the promise rejects). A dirty
workflow is different: `check()` resolves to a report so the caller can show
every finding — branch on `report.clean`, never log readiness while it is
false.

## Keep receipts governed

```text .gitignore
.nika/
.env
```

Everything under `.nika/` is machine state:

| Path | Holds |
|---|---|
| `.nika/traces/` | run records, which can carry model outputs, file contents and tool arguments |
| `.nika/arm/` | firing claims, receipts and cadence watermarks |
| `.nika/serve/` | `nika serve` job snapshots and schedule state |
| `.nika/serve.token` | the server's bearer token: a secret |
| `.nika/compile/` | recorded compile plans |
| `.nika/approval-claims/` | which human approvals were already used |
| `.nika/quarantine/` | outputs a failed run moved aside, one folder per trace |

<Warning>
  Never commit `.nika/serve.token`: it is the bearer token that lets a client
  run workflows on your server.
</Warning>

If a deployment retains this state, choose the volume, retention window and
access policy explicitly.

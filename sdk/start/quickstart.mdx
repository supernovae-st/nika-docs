Use Node.js 22 or newer. This example runs locally with the package's native
engine and the mock provider. It needs no server, global CLI or provider key.

## 1. Install in your application

```sh
npm install @supernovae-st/nika@0.118.7
npm ls @supernovae-st/nika
```

Keep optional dependencies enabled: they provide the native payload for your
supported platform. An explicit `bin` or `NIKA_BIN` overrides that payload;
omit both for this first run. The [local client](/sdk/local/client) explains
binary resolution and compatibility errors.

## 2. Save a workflow

Create `hello.nika.yaml` in the application directory:

```yaml
nika: hello-sdk
model: mock/echo
permits: {}
tasks:
  greet:
    infer:
      prompt: "Hello, Nika"
      max_tokens: 32
outputs:
  greeting: ${{ tasks.greet.output }}
```

This fixture has no external tools or effects. Choosing a mock model for an
arbitrary workflow does not disable that workflow's tools or permissions.
A project `nika.yaml` is optional for this example; the executable source is
`hello.nika.yaml`.

## 3. Run and observe

Save `demo.mjs` next to the workflow:

```js
import { Nika } from '@supernovae-st/nika'

const nika = new Nika({ cwd: process.cwd() })
const run = await nika.run('./hello.nika.yaml', {
  maxCostUsd: 0,
})

const watching = (async () => {
  for await (const event of nika.events(run)) {
    console.log(event.kind)
  }
})()

const result = await run.done
await watching

if (result.status !== 'succeeded') {
  console.error(result)
  process.exitCode = result.exitCode ?? 1
} else {
  console.log(result.outputs)
}

if (result.receipt) {
  const proof = await nika.traceVerify(result.receipt)
  console.log(proof)
}
```

Run the application:

```sh
node demo.mjs
```

The engine admits the workflow as part of execution. `check()` is available
for authoring and CI; it is not an extra required step before every `run()`.
The published native transport can return a handle before admission finishes.
A handle alone is not evidence that execution started. `run.done` reports the
terminal result; configuration, compatibility, transport or protocol errors
can reject and should be handled by your application's error boundary.

## 4. Read the proof's scope

Pass an engine-issued receipt to `traceVerify(receipt)` unchanged. Verification reads
existing evidence; it does not seal an unsigned journal. A mock run may have
an intact but unsealed trace, so `verified: false` alone does not mean the run
failed or that the journal is corrupt. Read the returned reason and details.
With this unsigned fixture, the published SDK can report `receipt_mismatch`
even while the engine reports an intact chain: the evidence has no verified
signed SDK receipt binding. This is not a verified receipt; the successful
workflow result and receipt verification are separate outcomes.
A trace does not prove that an external recipient read a message or that a
business goal was achieved.

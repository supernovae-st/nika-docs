Nika is not another agent. It is **the workflow file your agents already
run** — checked before, verified after. Integration therefore means two
small things: teach your agent the language, and wire the read-only oracle.

## Minute 0-2 · install the CLI

This 10-minute loop uses the **CLI** (`nika init`, `nika wire`,
`nika compile`). The later commands on this page require a `nika`
binary on `PATH`.

```sh
brew install supernovae-st/tap/nika    # or: curl -LsSf https://nika.sh/install.sh | sh
nika --version && nika doctor          # doctor prints exact fixes, never mutates
```

No key needed yet — `mock/echo` and local providers run without one.

Driving Nika from Node instead of a shell? That is a different door:
`npm install @supernovae-st/nika@0.123.2` inside a project bundles the
engine for your app and gives you `./node_modules/.bin/nika`, but does not
add `nika` to your `PATH`. Do not type `npx nika` outside such a project:
the unscoped npm name `nika` belongs to an unrelated package. Follow the
[SDK quickstart](/sdk/start/quickstart) (`run()` admits, `run.result()`
settles, `run.events()` yields normalized kinds).

## Minute 2-5 · teach the repo

```sh
nika init
```

One command writes the agent surface: `AGENTS.md` (read natively by Codex,
Claude Code, Cursor, OpenCode, Hermes, Jules and every AGENTS.md-aware
tool), `CLAUDE.md`, the Cursor rules and subagents, the Copilot
instructions, the repo-level [agent skill](https://agentskills.io), the
`.vscode` schema wiring, a commented `nika.yaml` and a starter workflow. It
also writes project MCP configs (`.mcp.json`, `.cursor/mcp.json`,
`.agents/mcp_config.json`) and Claude Code and Cursor hooks: shell scripts
those clients run at session start, after an edit and before a shell
command. Read them before you commit them
([every file `nika init` writes](/getting-started/agents#nika-init-teach-the-repo)).
Existing files are skipped.

## Minute 5-7 · wire the oracle

```sh
nika wire detected --dry-run   # preview what this machine shows
nika wire detected             # or one client: cursor · vscode · claude ·
                               # claude-desktop · codex · gemini · qwen ·
                               # opencode · hermes · zed · continue · cline ·
                               # lmstudio · junie · grok · kimi · antigravity ·
                               # kiro · copilot · amp · windsurf
```

`nika wire --help` lists every target on this binary. Clients with no
target (goose, Open WebUI, AnythingLLM, Cherry Studio, Jan) take the same
two-field stanza — copy it from [per-client wiring](/integrations/mcp-clients).
What the oracle exposes (and refuses to): [Nika as an MCP server](/reference/mcp-server).

## Minute 7-10 · prove the loop

Ask your agent:

> Create a workflow from the `chain` template that summarizes ./notes.md
> into ./out/brief.md, **check it**, then run it with the mock model.

The agent previews (`nika compile chain --json` — incomplete questions
stay questions; no file is written), answers them with repeatable
`--answer KEY=JSON_LITERAL`, writes a Ready destination, audits
(`nika check` — plan, cost floor, permits, **before** any token is
spent), runs offline (`--model mock/echo`), and the receipts land in
`.nika/traces/` (`nika trace verify` → exit 0: bare, it reads the latest
trace; the run card prints each trace's path on its `trace:` line).

## Then: CI receipts

Put [the GitHub Action](/integrations/github-actions) on the repo — every PR
that touches a `.nika` gets a sticky comment with the check verdict,
the honest cost floor, required secrets and the DAG. Check-only, zero
secrets, by default.

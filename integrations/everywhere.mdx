## Keeping the suite fresh

Every surface below invokes the **binary**, and the plugin kits ride its
release train — but no surface updates another: brew never touches a
plugin, a marketplace never touches the binary. The ladder, per surface:

| Surface | Update gesture | Note |
|---|---|---|
| **Binary** | `brew upgrade nika` | patch releases ship binary-only |
| **Claude Code plugin** | `claude plugin marketplace update nika` **then** `claude plugin update nika@nika` | TWO rungs — the clone, then the install; restart after |
| **Codex plugin** | `codex plugin marketplace upgrade nika` | the per-version cache refreshes on your next run |
| **Cursor** | marketplace installs self-manage; a local drop re-syncs via the kit's `scripts/update-mirrors.sh` | — |
| **Every surface at once** | `scripts/update-mirrors.sh` in a [nika-plugins](https://github.com/supernovae-st/nika-plugins) checkout | `--check` reports drift read-only (CI-able) |

<Info>
`nika doctor` is the coherence oracle: from v0.107 it reads what each
client actually loads, names any kit lagging or leading the binary's
train, and prints the exact per-client fix. Drift is advisory
(warn · exit 0) — a diagnosis never breaks automation.
</Info>

## SDKs & language surfaces

| Element | What it is | Where |
|---|---|---|
| **TypeScript SDK** | `@supernovae-st/nika@0.123.1` — one typed facade (`check` · `compile` · `run` · `run.events()` · `run.result()` · `traceVerify`) · Apache-2.0. `traceVerify` reads existing evidence; it does not seal, rerun, or prove the job was correct. | [SDK overview](/sdk/overview) · [source](https://github.com/supernovae-st/nika-client) |

## Learn the patterns first

New to agentic workflows as a concept?
[agentic-ai-systems](https://github.com/ThibautMelen/agentic-ai-systems)
explains the workflow taxonomy (chaining, routing, parallelization,
orchestrator and workers, evaluator and optimizer) with diagrams. Read it for
the ideas only: the files in its `patterns-as-code` folder use a retired file
suffix and the retired envelope (`nika: v1`, `vars:`), and 0.123.1 refuses
them. For patterns that run, use `nika try`, which lists the
worked path and the jobs and rehearses any of them offline, and the
[examples](/examples/overview).

</Tip>

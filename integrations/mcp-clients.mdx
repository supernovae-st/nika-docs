Every MCP-capable client wires the same read-only oracle
([what it exposes](/reference/mcp-server)) with the same two fields —
`command: nika` · `args: [mcp]`. The binary comes first:
`brew install supernovae-st/tap/nika` ([other paths](/getting-started/installation)).
This page is the matrix; every client has a dedicated page with the exact
file, shape, reload behavior and verify step.

One-click where the client supports it (binary still required first):

[![Install in VS Code](https://img.shields.io/badge/VS_Code-install%20nika%20mcp-0098FF?logo=githubcopilot)](https://insiders.vscode.dev/redirect/mcp/install?name=nika&config=%7B%22command%22%3A%20%22nika%22%2C%20%22args%22%3A%20%5B%22mcp%22%5D%7D)
[![Install MCP Server](https://cursor.com/deeplink/mcp-install-dark.svg)](https://cursor.com/en/install-mcp?name=nika&config=eyJjb21tYW5kIjogIm5pa2EiLCAiYXJncyI6IFsibWNwIl19)

And in every case, `nika init` first — the agent-teaching surface
(`AGENTS.md`, rules, the repo skill) is what makes the oracle useful.

## Wire what this machine has

The recommended door previews, then wires, every client this machine shows:

```sh
nika wire detected --dry-run   # the plan: created · updated · current · manual
nika wire detected             # write it
```

`nika wire <client>` wires one client by name, and `nika wire all` is the
advanced sweep over every supported client (previewed, then confirmed on a
terminal or with `--yes`). `nika wire --help` lists the targets your binary
knows.

Every `nika wire` write is idempotent (re-run prints `· current`) and
preserves unrelated servers.

The sections below give each client's essentials for directory deep-links;
most point to a dedicated page.

## Antigravity

`nika wire antigravity` → `~/.gemini/config/mcp_config.json`, the same
`mcpServers` stanza Gemini CLI uses:

```json
{ "mcpServers": { "nika": { "command": "nika", "args": ["mcp"] } } }
```

## Kiro

`nika wire kiro` → `~/.kiro/settings/mcp.json`, with the same `mcpServers`
stanza.

## GitHub Copilot CLI

`nika wire copilot` → `~/.copilot/mcp-config.json`, the machine-level
configuration. Copilot's local servers carry a type and a tool list:

```json
{ "mcpServers": { "nika": { "type": "local", "command": "nika", "args": ["mcp"], "tools": ["*"] } } }
```

Inside a repository, the `.mcp.json` and `AGENTS.md` that `nika init` writes
cover it too.

## Amp

`nika wire amp` → `~/.config/amp/settings.json`, under Amp's own key:

```json
{ "amp.mcpServers": { "nika": { "command": "nika", "args": ["mcp"] } } }
```

Amp also reads the `AGENTS.md` and `.agents/skills` that `nika init` writes.

## Neovim

Neovim reaches MCP through [mcphub.nvim](https://github.com/ravitemer/mcphub.nvim),
which serves avante and codecompanion. `nika wire` has no Neovim target: add
the stdio stanza by hand to mcphub's servers file, `~/.config/mcphub/servers.json`
by default.

```json
{ "mcpServers": { "nika": { "command": "nika", "args": ["mcp"] } } }
```

Nika's listing in the mcphub registry is a submission still under review
([ravitemer/mcp-registry#39](https://github.com/ravitemer/mcp-registry/pull/39)),
so the registry does not offer it yet.

## Aider

Aider reads repo conventions rather than MCP: `nika init`'s `AGENTS.md`
covers it (add `CONVENTIONS.md: AGENTS.md` to `.aider.conf.yml` if you keep
conventions elsewhere). The check loop is the same:
`nika check <file>` after every edit.

## Verify (any client)

Ask the agent to list its tools — the nine `nika_*` names should appear.
Then prove the loop end-to-end:
[integrate in 10 minutes](/integrations/quickstart).

> Client config formats move fast. The stable contract is the stanza
> (`nika` + `mcp`) and the oracle's read-only surface — if a client's
> documented path has moved, the stanza still applies.

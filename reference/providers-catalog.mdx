The language names **{CANON.providers} canonical providers**:
{CANON.providersLocal} local servers, {CANON.providersCloud} cloud APIs and
{CANON.providersTest} deterministic mock. The {STATUS.version} binary drives
exactly those. You select one with a single `model: <provider>/<name>` field.
**Your choice:** a local provider keeps inference on your machine; a cloud
provider runs only when a workflow names it.

<Info>
  **Canonical source:** [`stdlib/providers-v0.1.md`](https://github.com/supernovae-st/nika-spec/blob/6390b08eb9791ce49c63ee17f8466fab118cadb8/stdlib/providers-v0.1.md)
  in the specification the binary embeds. The engine's catalog
  ([`llm-providers.toml` at v0.123.0](https://github.com/supernovae-st/nika/blob/v0.123.0/crates/nika-catalog/data/llm-providers.toml))
  holds {STATUS.providers} records: `nika catalog` lists the
  {STATUS.providers - CANON.providers} it cannot drive under **CATALOG ONLY**,
  and `nika check` refuses them. Every table below matches
  `nika catalog --json` on v{STATUS.version}.
</Info>

## How to pick a provider

<Steps>
  <Step title="Pick where inference runs">
    A local server (Ollama, LM Studio, llama.cpp, LocalAI, vLLM, or Nika's own
    `nika model serve`) needs no key and sends nothing off the machine. A cloud
    API runs on your key, with that vendor's residency and compliance terms:
    Mistral and Scaleway are EU providers; OpenRouter and Hugging Face route
    many vendors' models under one key.
  </Step>
  <Step title="See what this machine has">
    `nika doctor` reports each provider key as set or unset, never its value.
    `nika doctor --ping` also connects to the configured local servers and
    reads their model lists.
  </Step>
  <Step title="Pick the model">
    Each provider declares a default and a cheap model (below).
    `nika catalog --json` lists every model with its context window, output
    cap and capabilities; the [capability rules](/reference/capabilities)
    decide its token-limit parameter, reasoning, modalities and JSON mode.
  </Step>
  <Step title="Check before you run">
    `nika check` prints a **MODELS** line (the model resolves in this build)
    and an **ACCESS** line (this machine has a path to it), without calling
    the model.
  </Step>
</Steps>

## By category

Local first, then cloud in the canon's presentation order.

<Tabs>
  <Tab title={`Local (${CANON.providersLocal})`}>
    | ID | Server · default endpoint | Default model |
    |---|---|---|
    | `ollama` | Ollama · `127.0.0.1:11434` (its native `/api/chat`) | `qwen3.5:4b` (cheap `llama3.2:3b`) |
    | `lmstudio` | LM Studio · `127.0.0.1:1234/v1` | `qwen3.5-4b` |
    | `llamacpp` | llama.cpp `llama-server` · `127.0.0.1:8080/v1` | `default` (the loaded GGUF; the id is free-form) |
    | `localai` | LocalAI · `127.0.0.1:8080/v1` | `default` |
    | `vllm` | vLLM · `127.0.0.1:8000/v1` | `Qwen/Qwen3-8B` |

    No key. `NIKA_<ID>_BASE_URL` points one at another host or port
    (`host`, `host:port` or a full URL; a bare host keeps the default port),
    and Ollama also honors `OLLAMA_HOST`. llama.cpp and LocalAI share port
    8080 by default: running both needs one override.

    <Tip>
      **Built-in local inference.** `nika model serve` starts an
      OpenAI-compatible server on `127.0.0.1:8712` (Qwen3-family models in
      0.124.1). A workflow reaches it as `llamacpp/<model id>` with
      `NIKA_LLAMACPP_BASE_URL=http://127.0.0.1:8712`. See
      [Local models](/guides/local-models).
    </Tip>
  </Tab>

    | `nvidia` | NVIDIA API | `openai-chat` | `NVIDIA_API_KEY` | `nvidia/nemotron-3-super-120b-a12b` | `nvidia/nemotron-3-nano-30b-a3b` |
    | `moonshot` | Moonshot (Kimi) | `openai-chat` | `MOONSHOT_API_KEY` | `kimi-k2` | `kimi-k2` |

    `NIKA_<ID>_API_KEY` (for example `NIKA_MISTRAL_API_KEY`) wins over the
    vendor variable. A model id the catalog does not list still resolves
    under a wired provider; `nika check` notes that it cannot price it.

    <Tip>
      **Any other OpenAI-compatible endpoint.** Set `NIKA_OPENAI_BASE_URL` to
      the server's complete endpoint and `NIKA_OPENAI_API_KEY` to its key, and
      keep `model: openai/<name>`. A workflow file has no `base_url:` field.
    </Tip>
  </Tab>

  <Tab title="Test (1)">
    | ID | Models | Env var |
    |---|---|---|
    | `mock` | `mock/echo` · `mock/mock-default` | none |

    <Note>
      **Mock** ships with every install: it echoes the prompt with no network
      and no key, and synthesizes a conformant value for a `schema:`. The
      canonical examples, `nika try` and `nika test` rely on it. A mock model
      does not make real tools or effects mock: an `exec:` or a `nika:write`
      still runs.
    </Note>
  </Tab>
</Tabs>

    `native` · `perplexity` · `qwen` · `replicate` · `sambanova` ·
    `together` · `vertex` · `voyage` · `writer` · `zhipu`

    They are records, not routes: `nika check` refuses a model under any of
    them, and `nika catalog` prints them under **CATALOG ONLY**. Reach an
    OpenAI-compatible one through `NIKA_OPENAI_BASE_URL` as above.
  </Accordion>

## Example: a local model with a cloud fallback

<CodeGroup>
```yaml workflow.nika
nika: multi-provider
permits: {}

tasks:
  primary:
    on_error: { skip: true }   # a dead provider skips (error preserved) · the gate below reads it
    infer:
      model: ollama/qwen3.5:4b               # local · zero key
      prompt: "Explain linear algebra in one sentence."
      max_tokens: 200

  fallback:
    with:
      problem: ${{ tasks.primary.error }}   # failure-observation edge · a skip carries its preserved error
    when: "${{ with.problem != null }}"     # local read of the binding
    infer:
      model: mistral/mistral-small-latest
      prompt: "Explain linear algebra in one sentence."
      max_tokens: 200

outputs:
  local: ${{ tasks.primary.output }}       # null when the local model failed
  cloud: ${{ tasks.fallback.output }}      # null when it did not need to run
```

```bash Required env
ollama pull qwen3.5:4b          # local primary · no key
export MISTRAL_API_KEY=...      # cloud fallback only
nika check workflow.nika
nika run workflow.nika --max-cost-usd 0.05
```
</CodeGroup>

A task names one model: there is no `fallback:` field. The second task runs
only when the first one failed, and `--max-cost-usd` bounds the metered spend.

Nika (legacy `nikab` binary) ships with **63 built-in tools across 10 categories**.
They are engine-native — no MCP round-trip, no subprocess — and invoked under the
`nika:*` namespace from workflow YAML via the `invoke:` verb.

<Info>
  **Canonical source:** [`crates/nika-catalog/src/data/builtins.rs`](https://github.com/supernovae-st/nika/blob/nika-diamond/crates/nika-catalog/src/data/builtins.rs) —
  the `ALL_BUILTINS` static array is sorted alphabetically and served
  via `O(log n)` binary search. Snapshot 2026-04-17.
  Invariants (checked by unit tests): array length = 63, strictly
  sorted, case-sensitive, `Core` = 7, `File` = 5, `Data` = 13.
</Info>

## How to invoke one

<CodeGroup>
```yaml workflow.nika.yaml
nika: v1
workflow: read-and-transform

tasks:
  - id: load
    invoke:
      tool: nika:read        # builtin under nika:*
      input:
        path: ./data.json

  - id: shape
    depends_on: [load]
    invoke:
      tool: nika:jq
      input:
        expr: ".records[] | select(.active)"
        data: "{{ tasks.load.output }}"
```

```rust Lookup from Rust
use nika_catalog::{find_builtin, is_known_builtin};

assert!(is_known_builtin("jq"));
let b = find_builtin("pipeline").unwrap();
assert_eq!(b.name, "pipeline");
```
</CodeGroup>

<Note>
  The `invoke:` verb crate lands in Round 7 — at v{STATUS.version} the
  YAML above is the target design. Catalog lookup (`find_builtin`) is
  already public API on the admitted `nika-catalog` crate.
</Note>

## Core — primitive control flow (7)

Sequencing, logging, assertions, and timing primitives.

| Tool | Purpose |
|---|---|
| `nika:assert` | Assert a predicate; fail the task on violation. |
| `nika:complete` | Mark the current task complete (explicit terminator). |
| `nika:emit` | Emit a structured event into the run log. |
| `nika:log` | Write to the run log at a chosen level. |
| `nika:prompt` | Prompt the user interactively (TUI / serve only). |
| `nika:run` | Run a nested workflow or skill. |
| `nika:sleep` | Pause for a duration (test-safe; backed by injectable `Clock`). |

## File — local I/O (5)

Path-based filesystem access, mediated by the `Fs` kernel trait.

| Tool | Purpose |
|---|---|
| `nika:edit` | Edit a file in place with a patch or diff. |
| `nika:glob` | Glob-match files under a directory. |
| `nika:grep` | Ripgrep-style content search across files. |
| `nika:read` | Read a file (text or blob). |
| `nika:write` | Write a file atomically. |

## Data — collection and JSON shaping (13)

Everything-is-data transformations that run in-memory.

| Tool | Purpose |
|---|---|
| `nika:chunk` | Split a sequence into fixed-size or token-aware chunks. |
| `nika:enrich` | Add fields to each record via lookup or computation. |
| `nika:filter` | Keep records that match a predicate. |
| `nika:group_by` | Partition records by a key. |
| `nika:inject` | Merge a value into a path inside a document. |
| `nika:jq` | Run a jq expression over JSON. |
| `nika:json_diff` | Diff two JSON documents into RFC 6902 patches. |
| `nika:json_merge` | Merge two JSON documents (shallow or deep). |
| `nika:map` | Apply a transform to each record. |
| `nika:set_diff` | Set difference between two sequences. |
| `nika:token_count` | Count tokens for a given tokenizer. |
| `nika:tree_data` | Walk or shape a nested document. |
| `nika:zip` | Zip two or more sequences into tuples. |

   5   category: MediaAlwaysOn,
   5   category: File,
   4   category: Introspection,
   3   category: MediaCore,

17 + 13 + 7 + 6 + 5 + 5 + 4 + 3 + 2 + 1 = **63**, matching
`ALL_BUILTINS.len() == 63` asserted by `builtin_count`.

<Tip>
  The builtin set is intentionally curated. The bar for a new entry is
  high: it must be a pure function of inputs + kernel traits (no hidden
  I/O), serialize deterministically, and justify why it cannot be a
  skill or an MCP tool instead.
</Tip>

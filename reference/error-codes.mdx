Every error Nika emits carries a unique `NIKA-XXX` code. The wire format
is `NIKA-{num:03}` (3-digit zero-padded under 1000, more otherwise) —
stable across versions, machine-parseable, serde-serializable.

<Info>
  **Canonical source:** [`crates/nika-error/src/codes.rs`](https://github.com/supernovae-st/nika/blob/nika-diamond/crates/nika-error/src/codes.rs)
  defines the `NikaCode` type and the 14 codes owned by `nika-error` itself;
  downstream crates (`nika-kernel`, `nika-catalog`, `nika-schema`, …)
  register their own codes via the [`NikaErrorCode`](https://github.com/supernovae-st/nika/blob/nika-diamond/crates/nika-error/src/traits.rs)
  trait. This page enumerates every code defined by crates admitted at
  v{STATUS.version}. Snapshot: 2026-04-17.
</Info>

## Anatomy of a code

Each code is a `NikaCode` struct with four fields:

| Field | Type | Purpose |
|---|---|---|
| `num` | `u16` | Numeric identifier, unique across the registry (1..=9999) |
| `category` | `Category` | Functional grouping — routes to the right handler |
| `severity` | `Severity` | `Error` or `Warning` |
| `slug` | `&'static str` | Kebab-case identifier for docs URLs (e.g., `validation-failed`) |

Codes that flow through transient-aware handlers also answer
`is_transient() -> bool` — `true` for rate-limited, 5xx, and timeout
variants; callers use this to decide whether to retry.

## Category ranges

Ranges are a documented convention in `codes.rs`. They are **not enforced
at the type level**: any crate can define a code in any range as long as
the number is unique.

| Range | Category | Owner crate | Notes |
|---|---|---|---|
| 001–049 | `Core` | `nika-error`, `nika-catalog` | Input validation, catalog parse, pricing, context-window |
| 050–099 | `Shell` | `nika-kernel` | Process spawn, timeout, cancel, security block |
| 100–139 | `FileIo` | `nika-kernel` | Blob not-found, I/O, size limits |
| 140–189 | `Http` | `nika-kernel` | Timeout, connection, SSRF, size, unsupported |
| 190–229 | `Auth` | reserved | — |
| 230–279 | `Mcp` | `nika-kernel` | Tool lookup + execution |
| 280–329 | `Schema` | `nika-schema` (WIP) | YAML parse, DAG validation, structured-output checks |
| 330–379 | `Binding` | reserved | — |
| 380–429 | `Provider` | `nika-kernel` | Provider API, rate limit, auth, model lookup |
| 430–479 | `Verb` | reserved | — |
| 480–529 | `Runtime` | reserved | — |
| 600–649 | `Memory` | `nika-kernel` | Store unavailable, embedding, storage |
| 700–749 | `WasmPlugin` | `nika-kernel` | Plugin host errors (v0.100 seam) |
| 750–799 | `Sandbox` | `nika-kernel` | Capability denial, platform support |
| 800–819 | `Observability` | reserved | v0.100 OTel seam |
| 999 | `Core` | `nika-error` | Internal catch-all — [file an issue](https://github.com/supernovae-st/nika/issues) |

<Note>
  Ranges marked **reserved** are carved out in `codes.rs` for future
  crates but have no concrete codes at v{STATUS.version}. See the
  [crate constellation](/reference/constellation) for admission progress.
</Note>

## Core — `nika-error` (001–049)

Defined in [`crates/nika-error/src/codes.rs`](https://github.com/supernovae-st/nika/blob/nika-diamond/crates/nika-error/src/codes.rs).
These 9 codes are owned by `nika-error` itself; the rest of the
`Core` range is filled in by `nika-catalog` (NIKA-010..015) via the
`NikaErrorCode` trait.

| Code | Slug | Owner | Transient | Meaning |
|---|---|---|---|---|
| `NIKA-001` | `validation-failed` | nika-error | no | Input validation failed — check your workflow YAML syntax and field values. |
| `NIKA-002` | `not-found` | nika-error | no | Referenced item not found in catalogs or task outputs. |
| `NIKA-003` | `unsupported` | nika-error | no | Feature not supported in current configuration. |
| `NIKA-010` | `catalog-toml-parse` | nika-catalog | no | Catalog TOML is malformed. Check syntax near the reported line and column. |
| `NIKA-011` | `catalog-schema-mismatch` | nika-catalog | no | Catalog schema version does not match the expected version. Update the `schema` field. |
| `NIKA-012` | `capability-rule-conflict` | nika-catalog | no | Two capability rules conflict for the same scope. Check rule ordering in `model-capabilities.toml`. |
| `NIKA-013` | `pricing-axis-out-of-range` | nika-catalog | no | A pricing axis value is out of valid range. Ensure rates are non-negative and finite. |
| `NIKA-014` | `context-window-invariant` | nika-catalog | no | `max_output_tokens` exceeds `context_window_tokens`. Fix the model capability rule. |
| `NIKA-015` | `json-mode-unknown` | nika-catalog | no | Unrecognised `json_mode` value. Valid values: `none`, `object`, `schema`. |

<Note>
  Range 016–049 is reserved for additional core/catalog codes as new
  validation rules land.
</Note>

## Provider — `nika-kernel` (380–429)

`NikaErrorCode` impl for `ProviderError`. Provider errors are the only
range that flags `is_transient()` for retries.

| Code | Slug | Transient | Meaning |
|---|---|---|---|
| `NIKA-380` | `provider-api` | yes (5xx only) | Provider API returned an error. Transient for 500..=599. |
| `NIKA-381` | `provider-model-not-found` | no | Model not declared in the provider catalog. |
| `NIKA-382` | `provider-rate-limited` | **yes** | Provider rate-limited the request. Retry after `retry_after_ms`. |
| `NIKA-383` | `provider-auth-failed` | no | Authentication failed — check API key + org/project id. |
| `NIKA-389` | `provider-other` | no | Other provider error — see message. |

<Tip>
  `is_transient() == true` is the signal callers use to retry with
  backoff. Everything else is a caller-side bug or a misconfiguration —
  retrying won't help.
</Tip>

## Looking up codes programmatically

<CodeGroup>
```rust From the wire
use nika_error::codes::{lookup, NIKA_001};

assert_eq!(lookup("NIKA-001"), Some(NIKA_001));
assert_eq!(lookup("NIKA-042"), None); // not yet defined
```

```rust From the trait
use nika_error::traits::NikaErrorCode;
use nika_kernel::provider::ProviderError;

let err = ProviderError::RateLimited { retry_after_ms: Some(1200) };
assert_eq!(err.nika_code().num, 382);
assert!(err.is_transient()); // → retry
```

```rust Serde
use nika_error::codes::NIKA_001;

let wire = serde_json::to_string(&NIKA_001).unwrap();
assert_eq!(wire, "\"NIKA-001\"");
```
</CodeGroup>

<Warning>
  `nika_error::codes::lookup()` only resolves codes owned by
  `nika-error` itself (the Core range). Codes owned by downstream crates
  resolve via `NikaErrorCode::nika_code(&err)` directly. A
  workspace-level registry is tracked as future work — see the comment
  block in `codes.rs`.
</Warning>

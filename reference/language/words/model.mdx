## In a source template

Excerpt from `templates/agent-loop.nika`, source lines 30–39. This is a fragment, not a runnable workflow.

```yaml illustration
# not select a paid provider from ambient credentials. Choose a different
# model explicitly for a real run; `--model mock/echo` rehearses on the mock
# model: zero keys, no model call; a fetch step still reaches its host.
model: mock/echo

inputs:
  goal:
    type: string
    required: true
    # A `required:` input still carries a `default:` here so the skeleton
```

The pinned schema text says a `required` input is not satisfied by `default` (the caller must supply a value). The released 0.123.0 engine still applies `default:` when the key is omitted. That is a source-versus-implementation discrepancy ([nika-spec#348](https://github.com/supernovae-st/nika-spec/issues/348)), not one law. Prefer `required: false` plus `default:` for knobs, and required without `default:` for caller-owned values (`NIKA-1708` at run).

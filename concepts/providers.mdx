A task names its model as `<provider>/<name>`. The language specification
names **{CANON.providers} canonical providers**
([spec catalog](https://github.com/supernovae-st/nika-spec/blob/main/stdlib/providers-v0.1.md)),
and the 0.123.0 binary drives exactly those: {CANON.providersLocal} local
servers, {CANON.providersCloud} cloud APIs, and `mock`, the offline rehearsal
provider. The engine's catalog records {STATUS.providers} entries:
`nika catalog` lists the ones this build cannot drive under **CATALOG ONLY**,
and `nika check` refuses them.

<Tip>
  **Every provider with its environment variable and default model:**
  [Providers catalog](/reference/providers-catalog). `nika catalog` prints the
  same inventory from your binary.
</Tip>

| Kind | Providers |
|---|---|
| Local servers (no key) | `ollama` · `lmstudio` · `llamacpp` · `localai` · `vllm` |
| Cloud APIs (your key) | `mistral` · `scaleway` · `anthropic` · `openai` · `gemini` · `deepseek` · `xai` · `groq` · `openrouter` · `huggingface` · `nvidia` · `moonshot` |
| Rehearsal | `mock` (`mock/echo` echoes the prompt; no key, no network) |

Switching provider is **one line**:

```yaml
nika: hello-local
model: ollama/llama3.2:3b            # <provider>/<name> · swap to mistral/… · openai/… · mock/echo
permits: {}
tasks:
  first:
    infer:
      prompt: "Hello."
      max_tokens: 64
outputs:
  answer: ${{ tasks.first.output }}
```

A cataloged-only vendor is not a runnable one:

```text
$ nika check cohere.nika
 ✖ MODELS   `cohere/command-r` (task a) — provider `cohere` does not resolve in THIS binary
            (17 wired in this build (5 local · 12 cloud · plus mock) — `nika catalog` names them
            under LOCAL and CLOUD, this one under CATALOG ONLY); a cataloged vendor is not a runnable one
```

## Model and access

Two choices are separate. **The model** (`model:` in the file) picks the
intelligence. **The access path** picks how Nika reaches it:

| Access | What it uses |
|---|---|
| `local` | a server on this machine: Ollama, LM Studio, llama.cpp, LocalAI, vLLM, or Nika's own `nika model serve` |
| `api` | the provider's API, with your key from the environment (`MISTRAL_API_KEY`, `NIKA_MISTRAL_API_KEY`…) |
| `harness` | an agent app you are signed into: `claude-code` · `codex` · `copilot` · `gemini-cli` · `grok-build` · `kimi-code` · `opencode` · `qwen-code` |
| `mock` | the offline rehearsal |

Every `nika check` prints an **ACCESS** line and a final
`access ready ✔ | ✖` layer: whether this machine has a path to each model
the file names, without calling it. `nika run --access <class or seat>` pins
the path; a pin is a pin, so an unsatisfied one refuses before anything runs
and never substitutes another path or model. `nika doctor` lists the paths
your machine has. Read [Local models](/guides/local-models) and
[Harness access](/guides/harness-access) to set one up.

## One inference request for every provider

The engine turns every `infer:` and `agent:` step into one request type,
`InferRequest` (`crates/nika-kernel-ai/src/provider.rs`), whatever the
provider: the model, the messages, `temperature`, `max_tokens`, tools and
tool choice, the response format, stop sequences, a thinking budget, a
reasoning effort, provider extras, a timeout and a cancel handle, among
others. A provider is the combination of three small traits, `ProviderInfer`
(one call), `ProviderStream` (a streamed call) and `ProviderMeta` (its name
and capabilities), sealed so only the workspace implements the whole.

Every wire lives in one crate, `nika-providers`, which speaks three API
dialects plus the mock:

| Dialect | Providers in 0.123.0 | Notes |
|---|---|---|
| `openai-chat` | openai · scaleway · mistral · groq · deepseek · xai · huggingface · openrouter · moonshot · nvidia · ollama · lmstudio · llamacpp · localai · vllm | OpenAI's `/v1/chat/completions` shape, with a per-provider base URL and auth header |
| `anthropic` | anthropic | the native Messages API: tool use, extended thinking |
| `gemini` | gemini | the native `generateContent` API, structured output via `response_schema` |
| mock | mock | offline; synthesizes a conformant instance for a schema |

Any other OpenAI-compatible endpoint is reached by pointing a cataloged id at
it: `NIKA_<ID>_BASE_URL` (for example `NIKA_OPENAI_BASE_URL`) sets the
complete endpoint and `NIKA_<ID>_API_KEY` its key, and the file keeps
`model: openai/<name>`.

<Note>
  **Built-in local inference.** `nika model pull` downloads a GGUF model and
  `nika model serve` starts an OpenAI-compatible server on `127.0.0.1:8712`
  (Qwen3-family models in 0.123.0); a workflow reaches it as
  `llamacpp/<model id>` with `NIKA_LLAMACPP_BASE_URL` set. The `native/`
  catalog id is not wired in 0.123.0. See [Local models](/guides/local-models).
</Note>

## Capability rules

Every request is checked against
[capability rules](/reference/capabilities) before dispatch: defaults first,
then the first matching rule wins. The rules record:

- the **token-limit parameter** a model takes (`max_tokens`,
  `max_completion_tokens`…);
- whether the model **reasons** (a thinking model spends part of
  `max_tokens` on thinking);
- the **modalities** it accepts and returns (text, image…);
- whether **JSON mode** is unavailable, `object` or `schema`;
- which **parameters** it supports (temperature, stop sequences, system
  messages, reasoning effort…).

`nika check` reads them for its **MODELS** and **CAPACITY FIT** lines: a
reasoning model whose `max_tokens` leaves no room for an answer is refused
before any call, with the minimum to set.

## Structured output: the engine picks the wire (ADR-098)

A task's `schema:` is the single authored contract: there is no `json: true`
sugar and no per-provider knob. The engine decides, per run, how to honor it
on the wire the model speaks:

- **Fully specified schema** (every `object` has `properties`, every `array`
  has `items`): forwarded verbatim to the provider's strict structured mode
  where the wire has one.
- **Underspecified schema** (an `object` without `properties`, or an `array`
  without `items`): strict mode would reject it, so the engine requests the
  provider's native JSON mode instead, steers the shape through the prompt,
  and validates the reply locally against your schema, with bounded retry.
- **A wire with no native JSON mode** (the anthropic dialect): the prompt
  carries the shape; the same local validation applies.
- **The mock wire** receives the schema verbatim and synthesizes a
  conformant instance: this is what lets every schema workflow run offline
  under [`nika test`](/guides/testing).

Local validation is the constant floor across all wires: the provider's
strict mode is an optimization, never the guarantee.

## One model per task

A task names one model; there is no model fallback syntax (`fallback:` is
refused, `NIKA-PARSE-005`). To try another model when a task fails, add a
second task gated on `after: { primary: failure }` that names it; to give a
failed task a fallback value instead, use `on_error: { recover: … }`
([Patterns](/guides/patterns)).

## The wider catalog

The engine catalog ({STATUS.providers} entries) also records vendors this
build does not drive: Together, Fireworks, Cerebras, SambaNova, Cohere, AI21,
Bedrock, Azure, Vertex, Perplexity, Voyage, Qwen, MiniMax, Zhipu, DeepInfra,
Replicate, Hyperbolic, Writer, Databricks, Cloudflare and `native`. They are
records, not routes: `nika check` refuses each one. The catalog lives in the
engine's `llm-providers.toml` and is validated at build time.

## Adding a provider

Adding a provider is engine work: a `[[providers]]` block in
`llm-providers.toml` (id, environment variable, default model, `api_dialect`,
models), capability rules in `model-capabilities.toml` when the provider is
not standard, and a wire in `nika-providers`: an existing dialect needs only
a base URL and auth header. The [admission checklist](/architecture/admission)
applies.

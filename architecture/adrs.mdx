Every significant engineering decision in Nika Diamond lives as an ADR,
a short markdown file in [`docs/adr/`](https://github.com/supernovae-st/nika/tree/main/docs/adr)
with status, date, context, decision, consequences. At v{STATUS.version}:
**{STATUS.adrs} records**: {STATUS.adrsAccepted} accepted,
{STATUS.adrsProposed} proposed, {STATUS.adrsSuperseded} superseded and
{STATUS.adrsRejected} rejected. In the 0.124 line, work stays focused on
maintenance, security and the media capabilities workflows need, and the
proposed records stay as the record of open designs, not as a plan.

<Info>
  **Canonical source:** [`docs/adr/index.json`](https://github.com/supernovae-st/nika/blob/v0.123.0/docs/adr/index.json)
  (machine-readable) + [`docs/adr/README.md`](https://github.com/supernovae-st/nika/blob/v0.123.0/docs/adr/README.md)
  (human index). One file per ADR. An accepted ADR changes only by an
  amendment (a later ADR names it in its frontmatter `amends:` list) or by a
  superseding ADR.
</Info>

## How ADRs work

<Steps>
  <Step title="Propose">
    Any significant engineering decision starts as a Proposed ADR: a
    short markdown file in `docs/adr/adr-NNN-<slug>.md` with
    frontmatter: `id`, `title`, `status: Proposed`, `date`, `tags`,
    `related`. Writer describes the context, options considered, and
    recommended decision.
  </Step>
  <Step title="Review">
    Proposed ADRs are discussed in PRs. Others get `related:` /
    `supersedes:` / `requires:` links. Status can flip to Accepted or
    Rejected. The ADR index (`docs/adr/index.json`) is auto-regenerated.
  </Step>
  <Step title="Accept">
    Once accepted, an ADR changes only in two recorded ways: a later ADR
    **amends** it (listed in that ADR's `amends:`, with a banner in the
    amended file), or a new ADR **supersedes** it. `git log` tells you when
    and why a given rule came in.
  </Step>
  <Step title="Supersede">
    Rare, but when a decision proves wrong, a new Accepted ADR
    supersedes it. The superseded ADR stays in the tree with
    `status: superseded` and `superseded_by:`. Three supersessions exist:
    **ADR-021** (the K8s-style `apiVersion` envelope) by **ADR-082** (a
    single version marker), **ADR-082** by **ADR-113** (2026-08-13: the
    envelope's identity moves onto `nika:` itself, the version slot dies),
    and **ADR-116** (the first local-only `nika serve`) by **ADR-117**. One
    ADR is rejected outright (**ADR-089**) and kept in the tree as the
    record of a road not taken.
  </Step>
</Steps>

## Metadata fields

Every ADR carries rich metadata in both its frontmatter and `index.json`:

| Field | Purpose |
|---|---|
| `id` | `ADR-NNN` · assigned in ascending order, never reused. Not gap-free: ranges are reserved in blocks, so at v0.123.0 the tree runs `ADR-001`..`ADR-154` with 043-077, 101-104 and 151 unallocated |
| `title` | One-line decision summary |
| `status` | `Proposed` / `Accepted` / `Rejected` / `Superseded` |
| `date` | ISO date of last status change |
| `tags` | Free-form (e.g., `architecture`, `runtime`, `forward-compat`) |
| `affects_crates` | List of crate names the decision constrains |
| `affects_layers` | `L0`..`L5` · which layers feel the effect (L5 is reserved, not built) |
| `supersedes` | IDs this ADR replaces |
| `superseded_by` | ID that replaces this ADR |
| `related` | Sibling ADRs in the same design arc |
| `requires` | Prerequisite ADRs (this one makes no sense without them) |
| `enables` | Downstream ADRs this one unlocks |
| `amends` | Accepted ADRs this one amends in place, in the frontmatter only: `index.json` has no `amends` key (ADR-154 amends ADR-004, ADR-023 and ADR-143) |

## Gate 12 integration

<Check>
  Admission Gate 12 fails when a crate's commit changes a public API
  surface without either (a) being purely additive under
  `#[non_exhaustive]` rules, or (b) referencing an Accepted ADR that
  authorizes the break. The ADR trail is how breaking changes earn the
  right to exist.
</Check>
